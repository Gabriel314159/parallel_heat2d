Later on 29 October 2026, Anthropic Claude (Claude Code, local session; Claude Opus 5.5) listed what was missing before the HPC runs and, at the team's request, changed the parallel solver:

- Overlap in the conjugate gradient solve: with `--exchange overlap`, the halo exchange of the search direction now runs while $Ap$ is computed at the corners that read no process halo, and the edge corners follow once the exchange is complete. Before, only the pigment exchange overlapped. Files: `src/common/poisson.hpp`, `src/parallel/poisson_comm.hpp` (new; the MPI part of the CG moved out of `solver.cpp`) and `src/parallel/solver.cpp`.

- Phase timers for the time inside the CG's halo exchanges and global sums (`poisson_halo_s`, `poisson_sum_s`). The Poisson time and the CG iteration counts now cover the timed loop only; before, they included the spin-up.

From 30 October to 3 November 2026, Anthropic Claude (Claude Code, local session; Claude Sonnet 5.5, later Claude Opus 5.5) explained the parallel code (the halo exchange) to the team, helped draft the e-mail asking the lecturer for feedback on the progress report, and, after the lecturer's feedback, changed the following at the team's request:

- One thread per physical core: a second binding check finds the core each thread is bound to (`thread_cores` in `src/common/affinity.hpp`), and the ranks of a node compare the cores of their threads (`binding_over_nodes` in `src/parallel/decomposition.cpp`). It finds two threads on the hardware threads of one core even when they belong to different single-thread ranks, which the first check could not see. The run records the result as `binding` (`cores`, `unpinned`, `shared` or `unknown`) and warns unless it is `cores`. The job scripts set `OMP_PLACES=cores` and `OMP_PROC_BIND=close`, and `hpc/README.md` lists the launcher settings to check.
